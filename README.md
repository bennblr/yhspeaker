# LA2Speak — платформа голосовых серверов

Самостоятельно размещаемая платформа в духе TeamSpeak/Discord: админка создаёт
изолированные голосовые серверы, каждому можно привязать собственный домен.
Внутри сервера — голосовые каналы, текстовый чат, демонстрация экрана и модерация.
Два клиента: веб-версия и приложение для Windows (Electron).

Главная особенность: **администратор может говорить сразу во все каналы или выбранным
группам слушателей** — достаточно войти в любой голосовой канал с микрофоном и нажать
горячую клавишу нужного направления.

## Возможности

- Панель платформы: создание серверов, запуск/остановка/рестарт, привязка доменов,
  отдельные логин и пароль администратора каждого сервера.
- Полная изоляция арендаторов: свой процесс, JSON-хранилище, JWT-секрет и диапазон RTC-портов.
- HTTPS для привязанных доменов выпускается автоматически (Caddy + on-demand TLS).
- Голосовые каналы на базе SFU mediasoup (WebRTC, DTLS-SRTP), до 150 одновременных участников; лимит задаётся для каждого сервера в панели.
- Режим открытого микрофона и push-to-talk.
- Настройка микрофона: выбор устройства ввода/вывода, эхоподавление,
  нейросетевое шумоподавление, АКГ, усиление и чувствительность микрофона (шумовой гейт),
  индивидуальная громкость собеседников.
- Push-to-talk в Windows-клиенте работает глобально (даже когда окно свёрнуто):
  `V`, `B`, `Пробел`, `Alt+V`, `Ctrl+Space`.
- Вещание администратора включается горячими клавишами: отдельная клавиша для «Все каналы»
  и для каждой группы слушателей, назначается в настройках. В Windows-клиенте клавиши
  работают глобально, в том числе когда окно свёрнуто.
- Текстовый чат в каждом канале с историей и удалением сообщений.
- Демонстрация экрана (браузерный выбор окна/экрана, в Electron — системный выбор).
- Модерация: серверный мьют, кик, бан, гибкие роли с набором прав, создание и удаление каналов.
- Пароли каналов: защита голосового или текстового канала паролем и переименование каналов.
- Аккаунты и гости — по ссылке-приглашению или только по нику (настраивается в панели управления). Первый зарегистрированный аккаунт — администратор.
- Смена ника в настройках профиля; у администратора рядом с ником отображается значок щита.
- Светлая/тёмная тема, адаптивная вёрстка, веб-клиент устанавливается как PWA-подобная страница.
- В мобильной версии под шапкой закреплена панель голосового управления: микрофон,
  звук, демонстрация экрана и выход из канала всегда под рукой.

## Структура репозитория

```
shared/    общие типы и схемы для сервера и клиента
server/    Express + Socket.IO + mediasoup, JSON-хранилище одного сервера
web/       React + Vite + Tailwind: веб-клиент и админка платформы
platform/  control plane: панель, reverse proxy, запуск серверов-арендаторов
desktop/   Electron-клиент для Windows (NSIS-инсталлятор)
```

## Локальный запуск

Требования: Node.js 20+, npm 10+.

```bash
npm install
npm run dev
```

- Веб-клиент: http://localhost:5173 (Vite проксирует API и Socket.IO на порт 4000).
- Сервер: http://localhost:4000.

При первом запуске откройте веб-клиент и зарегистрируйте аккаунт — он получит роль
администратора. Дальше создавайте каналы и приглашайте людей.

`npm run dev` запускает один сервер. Мультисерверная платформа запускается отдельно:

```bash
npm run build             # web/dist и server/dist нужны платформе
npm run start:platform
```

- Админка: http://localhost:4100/platform, логин `admin`, пароль `admin12345`
  (пароль по умолчанию действует только вне production).
- Серверы получают порты 4200+ и домены вида `alpha.localhost`, открываются через
  тот же http://alpha.localhost:4100.
- Данные платформы и арендаторов: `platform-data/`.
- `npm run dev:platform` — то же самое с автоперезапуском control plane.

> Микрофон браузер разрешает только в защищённом контексте: `localhost` или HTTPS.
> При открытии по IP в локальной сети (http://192.168.x.x) браузер заблокирует микрофон.
> Домены `*.localhost` считаются защищённым контекстом.

Сборка production-версии одиночного сервера без платформы:

```bash
cp .env.example .env      # раскомментируйте блок «Одиночный сервер» и заполните JWT_SECRET и ANNOUNCED_IP
npm run build
NODE_ENV=production npm start
```

Сервер раздаёт собранный веб-клиент с того же порта (4000). Для интернета обязательно
поставьте HTTPS-прокси (Caddy/Nginx), иначе браузеры не дадут доступ к микрофону.

## Деплой на VPS (Docker + Caddy)

Проверено на Ubuntu 22.04/24.04. Минимально: 2 vCPU, 2 ГБ RAM, публичный IPv4.
Для нескольких активных серверов рекомендуем 4 vCPU, 4 ГБ RAM и канал от 100 Мбит/с.

Схема:

- контейнер `platform` слушает `127.0.0.1:4100`;
- каждый созданный сервер — отдельный процесс на `127.0.0.1:4200+`;
- Caddy принимает HTTPS на 80/443 и по заголовку Host проксирует запросы в платформу;
- mediasoup каждого сервера получает свой блок из пула UDP/TCP 40000–40999;
- поэтому оба контейнера работают в `network_mode: host`.

Панель и серверы наружу не публикуются: снаружи видны только 80/443 и RTC-порты.

### 1. DNS и порты

Создайте A-записи на публичный IP сервера для:

- домена самой панели, например `admin.example.com` (`PLATFORM_HOST`);
- каждого домена, который позже привяжете к серверу.

Заранее знать все домены не нужно: Caddy выпускает сертификат по запросу, когда домен
уже привязан в панели. Но A-запись должна существовать до первого открытия.

Откройте порты:

```bash
sudo ufw allow 22/tcp
sudo ufw allow 80,443/tcp
sudo ufw allow 40000:40999/tcp
sudo ufw allow 40000:40999/udp
sudo ufw enable
```

Если у облачного провайдера есть свой firewall/security group — откройте те же порты там.
Порты 4100 и 4200+ наружу не публикуются.

### 2. Docker

```bash
curl -fsSL https://get.docker.com | sh
sudo systemctl enable --now docker
```

### 3. Конфигурация

Скопируйте проект на сервер, например в `/opt/la2speak`, и создайте `.env`:

```bash
cd /opt/la2speak
cp .env.example .env
openssl rand -hex 32        # PLATFORM_JWT_SECRET
openssl rand -hex 32        # PLATFORM_SECRET_KEY (другая строка)
nano .env
```

Обязательно проверьте:

| Переменная | Значение |
|---|---|
| `PLATFORM_HOST` | домен панели без `https://`, например `admin.example.com` |
| `PLATFORM_TENANT_DOMAIN_SUFFIX` | необязательный суффикс автодоменов, например `example.com`: сервер без указанных доменов получает `<название>.example.com` (нужна wildcard A-запись `*`) |
| `PLATFORM_JWT_SECRET` | случайная строка от 16 символов (лучше 64 hex) |
| `PLATFORM_SECRET_KEY` | отдельная случайная строка: ею шифруются пароли серверов |
| `PLATFORM_ADMIN_LOGIN` / `PLATFORM_ADMIN_PASSWORD` | вход в панель платформы |
| `ANNOUNCED_IP` | **публичный IPv4** сервера (не 127.0.0.1) |
| `PLATFORM_HTTP_PORT_START` / `END` | пул портов арендаторов, по умолчанию 4200–4299 |
| `PLATFORM_RTC_POOL_START` / `END` | общий пул mediasoup, по умолчанию 40000–40999 |
| `PLATFORM_DEFAULT_MAX_PARTICIPANTS` | лимит участников для новых серверов, от 1 до 150 (по умолчанию 50) |
| `ALLOW_GUESTS` / `GUEST_INVITE_REQUIRED` | значения по умолчанию для новых серверов |

Лимит участников задаётся для каждого сервера отдельно при создании и в настройках.
Каждому голосовому участнику нужно два RTC-порта (отправка и приём), поэтому сервер
с лимитом `N` занимает `2N` портов из пула.

Вместимость платформы ограничена HTTP-портами (`END - START + 1` серверов) и пулом RTC:
сумма лимитов всех серверов не может превысить `(RTC_END - RTC_START + 1) / 2`.
При значениях по умолчанию это 100 HTTP-слотов и 500 участников суммарно, например
10 серверов по 50 человек или 3 сервера по 150. Увеличьте пул и откройте новые порты
в firewall, если нужно больше.

Пароли администраторов серверов хранятся в `platform.json` в зашифрованном виде.
Смена `PLATFORM_SECRET_KEY` сделает их нечитаемыми — используйте один ключ постоянно.

### 4. Запуск

```bash
docker compose up -d --build
docker compose logs -f platform caddy
```

Первый запуск занимает несколько минут: устанавливаются зависимости и собираются
клиент, сервер и платформа. Откройте `https://admin.example.com/platform` и войдите
с `PLATFORM_ADMIN_LOGIN` / `PLATFORM_ADMIN_PASSWORD`.

Порядок работы:

1. Нажмите «Новый сервер», задайте название, домен (например `chat.example.com`) и лимит
   участников от 1 до 150.
2. Скопируйте показанные логин и пароль администратора сервера — они понадобятся
   для входа на сам сервер.
3. Убедитесь, что A-запись домена указывает на VPS, и откройте
   `https://chat.example.com`. Caddy выпустит сертификат автоматически.
4. Домены и лимит участников можно менять позже в настройках сервера. Смена лимита
   пересчитывает диапазон RTC-портов и перезапускает сервер. Один домен нельзя
   привязать к двум серверам одновременно.

Остановка сервера в панели завершает его процесс, но не удаляет данные. Удаление
сервера стирает его запись и каталог данных — действие необратимо.

### 5. Обновление

```bash
cd /opt/la2speak
git pull
docker compose up -d --build
```

Данные лежат в томе `platform-data` и переживают пересборку контейнера.

### Резервная копия

```bash
cd /opt/la2speak
docker run --rm -v la2speak_platform-data:/data -v "$PWD":/backup alpine \
  tar czf /backup/la2speak-platform-$(date +%F).tgz -C /data .
```

Для консистентной копии остановите платформу на несколько секунд:
`docker compose stop platform`, скопируйте том, затем `docker compose start platform`.
В томе находятся `platform.json`, пароли серверов и данные всех арендаторов.

## Администрирование

Панель открывается кнопкой с щитом в сайдбаре. Её вкладки видны тем, у кого есть
соответствующие права: администратор видит всё, участник — только доступные разделы.

- **Каналы** — создание, переименование и удаление голосовых/текстовых каналов, пароли каналов.
- **Роли** — конструктор ролей: название, цвет и набор прав.
- **Группы** — группы слушателей вещания с выбором участников.
- **В сети** — серверный мьют, кик, бан, авторизация гостей.
- **Аккаунты** — выдача ролей, бан/разбан зарегистрированных пользователей.
- **Приглашения** — режим доступа гостей (по коду или только по нику), ссылка-приглашение и её перегенерация.

### Роли и права

Роли позволяют выдавать возможности, не делая участника администратором. В панели
управления → **Роли** создайте роль, выберите цвет и отметьте права:

| Право | Что разрешает |
|---|---|
| Вещание | Говорить во все голосовые каналы и группы слушателей |
| Модерация | Серверный мьют, кик, бан, удаление сообщений |
| Каналы | Создавать, переименовывать и удалять каналы, задавать и снимать пароли |
| Роли | Создавать и изменять роли, выдавать их участникам |
| Группы | Настраивать группы слушателей вещания |
| Приглашения | Настраивать доступ гостей и перегенерировать гостевой код |

Роль выдаётся во вкладке **Аккаунты** кнопкой с щитом: отметьте одну или несколько
ролей и сохраните. У участника может быть несколько ролей — права складываются.
Изменения применяются сразу: у получившего право вещания в настройках появляется блок
горячих клавиш вещания, у потерявшего — активное вещание останавливается и клавиши
перестают срабатывать. Цвет и название роли видны рядом
с именем в списке участников, на голосовой сцене и в аккаунтах.

Встроенные правила:

- Администратор всегда обладает всеми правами, роли ему не нужны.
- Гостям роли не выдаются, пока администратор не авторизует гостя в участника.
- Назначить администратора может только администратор.
- Удаление роли снимает её у всех участников и сразу пересчитывает их права.


### Пароли каналов

В панели управления → **Каналы** пароль задаётся при создании канала или позже кнопкой
с карандашом. Там же можно переименовать канал и сменить его пароль; поле «Снять пароль»
открывает канал всем.

- Пароль хранится на сервере только в виде bcrypt-хеша и никогда не передаётся клиентам.
- В списке каналов защищённые отмечены замком. При входе клиент спрашивает пароль.
- Права на канал действуют до конца сессии: после переподключения пароль нужно ввести снова.
- Администраторы входят в защищённые каналы без пароля. Гостям по-прежнему доступен только
  гостевой канал, и защитить его паролем нельзя.
- Пароль проверяется при отправке сообщений, чтении истории и входе в голосовой канал,
  поэтому обойти его через прямой запрос к API не получится.


### Вещание администратора

Администратор может говорить сразу во все каналы или только выбранным группам слушателей.
Кнопок вещания в интерфейсе нет — каждое направление включается своей горячей клавишей,
а назначение клавиш находится в настройках.

1. Зайдите в любой голосовой канал с активным микрофоном.
2. Откройте настройки (шестерёнка внизу панели) → блок **«Горячие клавиши вещания»**.
3. Назначьте клавиши:
   - **Все каналы** — вас слышат все участники сервера;
   - **название группы** — вас слышат только участники этой группы, в каком бы канале они ни были.
   Направления можно комбинировать: «Все каналы» и несколько групп одновременно. Клавиша
   переключает направление, повторное нажатие выключает его. Одна клавиша не может быть
   назначена двум направлениям или совпадать с клавишей push-to-talk — такие варианты
   помечаются в настройках.
4. Нажмите назначенную клавишу — сервер автоматически подпишет нужных участников на ваш
   микрофон: у них появится баннер вещания, а в списке участников — значок радио.
5. Баннер вещания в клиенте показывает активные направления и кнопку **Остановить** —
   она выключает вещание целиком.

В приложении для Windows горячие клавиши вещания работают глобально, в том числе когда
окно свёрнуто. В браузере они срабатывают, когда вкладка активна.

Группы создаются в панели управления → **Группы** (право «Группы»): задайте название и
отметьте зарегистрированных участников. Гостя нельзя добавить в группу — гости слышат
только вещание «Все каналы».

### Гости

На сервере автоматически создаётся голосовой канал **«Гостевая»** — его нельзя удалить,
и он виден всем участникам. Доступ гостей настраивается в панели управления →
**Приглашение** (право «Приглашения»):

- **По умолчанию код не нужен**: гость открывает сервер, выбирает вкладку «Гость» и вводит
  только ник.
- **Требовать код приглашения** включено — гости входят по ссылке
  `https://<сервер>/?guest=<код>` или вводят код вручную на вкладке «Гость».

Режим сохраняется в `data/store.json` и применяется сразу, без перезапуска сервера.
`GUEST_INVITE_REQUIRED` в `.env` задаёт только начальное значение для нового хранилища
(по умолчанию `false` — вход по нику).

1. Гость вводит имя — регистрация не нужна.
2. Гость видит и может войти только в гостевой канал; в нём есть голос и чат.
3. Администратор открывает **В сети** и нажимает у гостя кнопку с галочкой
   «Авторизовать гостя». Гость становится участником, получает доступ к остальным
   каналам и появляется во вкладке **Аккаунты**, где ему можно выдать роли.
4. Сгенерированные логин и пароль показываются администратору один раз — их можно
   передать гостю, чтобы он мог входить обычным способом.

Перегенерация кода делает старые ссылки недействительными (актуально в режиме с кодом).
Авторизованный гость сохраняется в аккаунтах: текущая сессия продолжает работать, а новые
входы выполняются по выданному логину и паролю. Неавторизованный гость существует только
в текущей сессии — после её окончания он входит снова по нику или по новой ссылке.

### Микрофон и чувствительность

Настройки открываются кнопкой с шестерёнкой в нижней части панели.

- **Усиление микрофона** — общая громкость вашего сигнала (0–200 %).
- **Чувствительность микрофона** — порог шумового гейта в открытом режиме. Ползунок
  находится прямо в блоке «Проверка микрофона». Чем правее, тем на более тихий голос
  реагирует микрофон. Звук ниже порога не передаётся, поэтому вентилятор, клавиатура и шум
  улицы не попадают в эфир.
- **Шумоподавление** — нейросетевая модель DeepFilterNet3 в аудиопотоке: убирает кашель,
  клавиатуру, вентилятор и уличный шум. Модель (около 23 МБ) скачивается один раз на
  устройство и подгружается заранее в простое; пока она грузится, звук идёт без неё.
  Шумоподавление браузера при этом отключено, чтобы не поднимать шум вместе с голосом.
  Если модель не загрузилась, остаются срез низких частот (120 Гц) и порог.
- **Громкость собеседника** — кнопка с ползунками в карточке участника и рядом с ником в
  списке пользователей голосового канала: от 0 до 200 %, отдельно для каждого человека.
  Настройка хранится на устройстве и действует только на вас; быстрые кнопки возвращают
  100 % или заглушают участника.
- Оранжевая риска на индикаторе «Проверка микрофона» показывает текущий порог: полоса
  должна доходить до неё, когда вы говорите, и оставаться ниже в тишине.
- «Слышать себя» идёт через тот же фильтр, нейросетевое шумоподавление, гейт и усиление,
  поэтому в наушниках слышно ровно то, что уходит в канал.
- В режиме push-to-talk порог не применяется — звук передаётся, пока удерживается клавиша.
- Гейт работает в аудиопотоке (AudioWorklet), поэтому продолжает работать при свёрнутом окне.

## Windows-клиент

Сборка выполняется на Windows с Node.js 20+:

```bash
npm install
npm run dist:desktop
```

Готовый установщик: `desktop/release/LA2Speak-Setup-1.0.2.exe` (NSIS, x64).

Установщик можно раздавать прямо из голосового канала. Положите `.exe` в каталог
`desktop-installer/` рядом с `docker-compose.yml` (или задайте свой каталог в
`DESKTOP_INSTALLER_DIR`). Сервер отдаёт самый свежий файл по адресу `/download/windows`,
а в веб-клиенте у пользователей десктопного браузера появляется кнопка «Скачать .exe».
В приложении Electron и на мобильных устройствах она скрыта. Тот же файл отдаёт и
панель платформы: в её шапке есть кнопка **«Клиент»** со ссылкой на
`https://<домен платформы>/download/windows`. Локально сервер берёт файл
из `desktop/release/`.

```bash
scp desktop/release/LA2Speak-Setup-1.0.2.exe root@<сервер>:/opt/la2speak/desktop-installer/
cd /opt/la2speak
docker compose up -d platform
```

Особенности:

- Установщик не подписан сертификатом, поэтому SmartScreen может показать предупреждение:
  «Подробнее» → «Выполнить в любом случае». Для публичного распространения рекомендуется
  купить код-сигнинг сертификат и настроить `win.certificateFile` в `desktop/package.json`.
- Если electron-builder падает при распаковке `winCodeSign` с ошибкой создания символических
  ссылок, включите в Windows «Режим разработчика» (Параметры → Система → Для разработчиков)
  или запустите терминал от имени администратора.
- При первом запуске клиент сразу подключается к `https://la2speak.com` (домен задан
  в `desktop/main.js`). Ввести другой сервер можно полным адресом
  `https://chat.example.com`, именем хоста `chat.example.com` или коротким именем
  `chat` — тогда клиент подключится к `chat.la2speak.com`. Адрес запоминается; сменить его
  можно кнопкой **«Сервер»** в верхней шапке приложения.
- Окно клиента использует собственную шапку в стиле приложения вместо стандартной рамки
  Windows: в ней есть название сервера, состояние подключения и кнопки свернуть /
  развернуть / закрыть. Шапку можно перетаскивать, двойной щелчок разворачивает окно.
- Глобальный push-to-talk использует низкоуровневый хук клавиатуры (`uiohook-napi`),
  поэтому сочетание срабатывает даже в свёрнутом окне. В веб-версии PTT работает только
  при активной вкладке.
- Демонстрация экрана в Electron открывает системный выбор экрана/окна Windows.

## Диагностика

**Подключаюсь к каналу, но никого не слышно.**

1. Проверьте, что открыты UDP **и** TCP порты 40000–40999.
2. `ANNOUNCED_IP` должен быть публичным IP сервера, а не `127.0.0.1`.
3. `docker compose logs -f platform` показывает запуск серверов; подробный лог
   каждого сервера лежит в `platform-data/logs/<id>.log` внутри тома.
4. `https://домен-сервера/api/health` показывает версию и число голосовых сессий.
5. Корпоративные сети и некоторые мобильные операторы блокируют UDP. TURN-сервер
   в этой версии не предусмотрен, поэтому в таких сетях голос может не работать.

**Браузер не даёт доступ к микрофону.** Нужен HTTPS (или `localhost`). Проверьте
разрешения сайта в настройках браузера.

**Caddy не выдаёт сертификат.** Проверьте A-запись домена, что порты 80/443 открыты,
домен привязан в панели (не только в DNS) и что `PLATFORM_HOST` указан без схемы и слэша.
Caddy спрашивает разрешение у `http://127.0.0.1:4100/api/tls/ask` — платформа отвечает
200 только для домена панели и доменов, привязанных к серверам.

**Платформа не стартует с ошибкой секрета.** В production обязательны
`PLATFORM_JWT_SECRET` (от 16 символов) и `PLATFORM_ADMIN_PASSWORD`. Если задан
`PLATFORM_SECRET_KEY`, не меняйте его без необходимости: им зашифрованы пароли серверов.

**В Windows-клиенте не работает глобальный PTT.** Антивирус может блокировать
низкоуровневый хук клавиатуры. Добавьте приложение в исключения. В браузере PTT
работает только при активном окне — это ограничение браузера, а не сервера.

**Ошибка «Не удалось подключиться к серверу».** Проверьте, что адрес начинается с
`https://`, сервер доступен с телефона/другого ПК и сертификат валиден.

## Ограничения

- Каждый сервер — JSON-хранилище (`platform-data/tenants/<id>/data/store.json`)
  и отдельный процесс с настраиваемым лимитом от 1 до 150 одновременных голосовых
  участников. Платформа запускает несколько таких процессов на одной машине, но не
  масштабирует один сервер горизонтально и не переносит его на другую машину.
- Один аудиомикшер mediasoup на процесс: для 150 участников лучше распределять людей
  по нескольким голосовым каналам. Если все находятся в одном канале, каждый получает
  149 аудиопотоков — это требует около 1 Гбит/с исходящего трафика и высокой нагрузки на CPU.
- Шифрование связи — DTLS-SRTP между клиентом и SFU; сквозного (E2E) шифрования нет.
- Нет TURN-релея: при жёстком NAT без UDP-связности голос может не установиться.
- Windows-клиент собирается только под x64. Мобильных приложений нет; веб-клиент
  работает в мобильном браузере, но глобальные клавиши (push-to-talk и вещание) доступны
  только в приложении для Windows.

## Безопасность

- Пароли хранятся в виде bcrypt-хешей, сессии — JWT.
- Для гостей и входа действуют ограничения частоты запросов.
- Не публикуйте порты 4100 и 4200+ напрямую и не запускайте серверы без HTTPS в интернете.
- Регулярно обновляйте зависимости (`npm audit`) и делайте резервные копии `platform-data/`.
